# Автоопределение количества вопросов по образцу варианта

Зависит от `explicit-source-kinds` (реализуется после неё): опирается на
пользовательский выбор типа `sample` и на отсутствие этапа `analyze_sources`.

## Problem

Количество вопросов в сгенерированном тесте всегда задаётся вручную (слайдер на
фронте, обязательное поле `num_questions` на бэке) и не связано с содержимым
документа. Если пользователь загружает образец/демоверсию с конкретным числом
заданий (например, 9), тест может получить произвольное число вопросов, не
совпадающее с образцом.

## Current behavior

- `backend/app/main.py`: `num_questions: int = Form(...)` — обязательное поле,
  валидируется как `1 <= num_questions <= settings.max_questions` сразу на входе.
- `backend/app/llm.py::build_user_prompt`: число подставляется в промпт напрямую —
  `"Составь ровно {num_questions} вопросов"` / `"НОВЫЙ тест из {num_questions}
  заданий"` (ветка `spec_like`).
- `frontend/src/components/UploadForm.tsx`: слайдер `numQuestions` (1..30,
  дефолт 10), значение всегда отправляется явно.
- Сегодня `SourceAnalysis.sample_tasks` (из `analyze_sources`) содержит список
  найденных заданий, но на количество вопросов не влияет. Спека
  `explicit-source-kinds` удаляет `analyze_sources` и `SourceAnalysis` целиком,
  поэтому считать `len(sample_tasks)` больше нечем.

## Solution

Решение (после отказа от LLM-анализа): **число вопросов определяет сама
генерирующая модель, а не отдельный предварительный подсчёт.**

Почему так. Варианты были: (A) отказаться от автоподсчёта; (B) вернуть
отдельный LLM-вызов "посчитать задания" — это по сути возвращает удалённый этап
анализа, ради которого CEO и убрал `analyze_sources`; (C) поручить подсчёт
основному вызову генерации. Выбран (C): нулевая доп. стоимость/задержка, а
пользователь уже явно сказал, что документ содержит образец (`sample`), то есть
условие применимости известно без классификации.

Правила:
1. `num_questions` становится опциональным (`Form(None)`). Явное значение всегда
   побеждает.
2. Если `num_questions` не передан и среди `source_kinds` есть `sample` — в промпте
   вместо фиксированного числа: "Количество заданий в новом тесте должно равняться
   количеству заданий в приведённом образце варианта (не более
   {max_questions})". Модель сама считает задания в тексте образца.
3. Если `num_questions` не передан и `sample` не выбран — дефолт `10` (текущий
   дефолт фронта), без ошибки.
4. Верхняя граница `settings.max_questions` (30) сохраняется: после генерации,
   если модель вернула больше, лишние вопросы отбрасываются с конца
   (предупреждение в лог). Нижнюю границу модель не гарантирует; пустой `questions`
   и так не проходит текущую логику ответа как валидный тест — специальной
   обработки сверх существующей не добавляем.
5. Явно переданный `num_questions` валидируется как сегодня (`1..max_questions`,
   `422` вне диапазона) — валидация остаётся на входе, перенос не нужен, так как
   анализ больше не участвует.
6. Число вопросов не проверяется на точное совпадение с образцом — подсчёт
   моделью best-effort (см. Out of scope).

## User stories / flow

1. Пользователь загружает демоверсию (9 заданий), отмечает тип "Образец варианта",
   включён переключатель "определить автоматически" → модель составляет тест из 9
   заданий.
2. Тот же документ, но пользователь выключил переключатель и выбрал 15 через
   слайдер → ровно 15 вопросов.
3. Пользователь загружает конспект (тип "Теория") — переключатель авто-режима не
   показывается, слайдер как сегодня.
4. Модель насчитала в образце 40 заданий → в ответе остаются первые 30 (лимит).

## Out of scope

- Точная гарантия совпадения числа вопросов с числом заданий образца — подсчёт
  делает LLM, возможны ошибки на нестандартной вёрстке.
- Отдельный LLM-вызов для подсчёта заданий (см. обоснование выше).
- Предпросмотр числа вопросов до отправки формы.
- Раздельный подсчёт по файлам — один набор типов и один общий контекст на запрос.
- Изменение `max_questions`.

## Acceptance criteria

- [ ] Без `num_questions` и с `sample` в `source_kinds` промпт просит число
      заданий, равное числу заданий образца (не более `max_questions`); число
      вопросов явно не подставляется.
- [ ] Без `num_questions` и без `sample` — 10 вопросов, без ошибки.
- [ ] Явный `num_questions` всегда побеждает; вне `1..max_questions` — `422`, как
      сегодня.
- [ ] Если модель вернула больше `max_questions` вопросов, ответ содержит первые
      `max_questions`.
- [ ] Фронтенд показывает переключатель авто-режима только при выбранном типе
      `sample`; при включённом — `num_questions` не отправляется.
