# Редизайн фронтенда — liquid glass

## Problem

Сегодняшний UI собран на голом Tailwind-утилитаре без единой визуальной
системы: обычные белые карточки, `slate`/`indigo` палитра, минимум обратной
связи (нет drag&drop, нет отдельного экрана теста, нет подтверждения при
неотвеченных вопросах). Экран непоследователен: форма, прогресс генерации,
ошибка и результат теста просто дописываются друг под другом на одной
странице.

Есть утверждённый CEO дизайн-макет ("Liquid glass для «Генератора тестов»",
Claude Design canvas) — стеклянные панели, единая палитра, типографика
(Onest + STIX Two Text для формул), готовые состояния всех экранов десктопа
и мобильной версии, а также заметки для разработчиков (состояния элементов,
анимации, адаптив, доступность). Нужно перенести этот дизайн на реальные
компоненты, не меняя бэкенд и модель данных, и добавить несколько уточнений
поведения, которые в макете оставлены на усмотрение реализации.

## Current behavior

- `frontend/src/App.tsx` — один экран: `UploadForm` → (если идёт запрос)
  `GenerationProgress` → (если есть ошибка) баннер ошибки → (если есть
  результат) `QuizView` рисуется ниже формы, форма никуда не убирается.
- `frontend/src/components/UploadForm.tsx` — нативный `<input type=file
  multiple>` без drag&drop, без списка выбранных файлов с удалением по
  одному (только список имён через запятую), без индикации "чего не
  хватает" для отправки.
- `frontend/src/components/QuizView.tsx` — один булевый `submitted` на весь
  тест; вопросы и результат показываются в одной и той же колонке, без
  отдельного экрана и без подтверждения при пустых ответах — "Проверить"
  сразу засчитывает пустые ответы как неверные.
- `frontend/src/components/GenerationProgress.tsx` — уже показывает
  реальный прогресс (`extract`/`generate`, `ExtractDetail` с
  `filename`/`processed`/`total`) из смерженной фичи `generation-progress`,
  но простым списком без анимации/визуала.
- `frontend/src/components/QuestionDiagram.tsx` — рендерит
  `diagram.image_base64` как обычный `<img>` без оформления.
- `frontend/src/components/RichText.tsx` — рендерит LaTeX через KaTeX
  инлайново в тексте (в том числе `$$...$$`/`\[...\]` блочные формулы), без
  отдельного визуального выделения блочных формул.
- Стилизация — Tailwind v4 (`@import "tailwindcss"` в `index.css`),
  utility-классы прямо в JSX.
- Тема, drag&drop, подтверждение при неотвеченных вопросах, отдельный экран
  теста — отсутствуют.

## Solution

### Объём

- Только светлая тема. Переключателя тем в шапке макета (иконка
  солнце/луна) не переносим — тема одна, кода на переключение нет.
- CSS макета (`Style.dc.html`: переменные, `.glass1`/`.glass2`/`.inset`,
  `.btn`/`.chip`/`.tile`/`.field`/`.opt`/`.card`/`.msg`/`.prog`/`.result`/
  `.loading` и т.д.) переносится в `frontend/src/index.css` практически
  1:1 — точные значения размеров, радиусов, цветов, теней и переходов
  сохраняются. Классы, привязанные к тёмной теме, `data-flat`, `data-m`
  (мобильный флаг для JS-детекции) и `data-anim` (появление карточек) не
  переносятся как переключаемые атрибуты — брейкпоинты остаются через
  media queries, анимация появления карточек включена всегда (без
  переключателя).
- `tailwindcss`/`@tailwindcss/vite` убираются из `frontend/package.json` и
  `frontend/vite.config.ts`, JSX переходит на классы дизайн-системы.
- Шрифты Onest (400/500/600/700) и STIX Two Text (для формул) подключаются
  через Google Fonts `<link>` в `index.html`, как в макете.
- Ни одна из существующих pydantic-схем/`GenerateResponse`/`ProgressState`
  не меняется — это чисто визуальная и клиентская поведенческая работа.

### Каркас экранов

`App.tsx` вместо "всё на одной странице" получает явный view-state:

```ts
type View = "form" | "loading" | "test" | "review";
```

- `form` — стартовый экран, форма загрузки (секции 1–5 показываются сразу,
  без постепенного раскрытия).
- При сабмите формы → `loading` (полноэкранная панель ожидания, форма
  скрыта).
- По получении результата → `test`, если в тесте есть хотя бы один вопрос
  без ответа; ответы на вопросы копятся в этом состоянии как сегодня.
- Нажатие «Проверить» (после подтверждения — см. ниже) переводит в
  `review`: те же карточки вопросов, но с показанными вердиктами, плюс
  карточка результата.
- «Пройти заново» на экране результата возвращает в `test` с очищенными
  ответами (тот же `quiz`, новый прогон). «Создать новый тест» возвращает в
  `form` (сброс `quiz`/`result`, форма показывается заново — с уже
  введёнными значениями полей, поля формы не сбрасываются автоматически,
  т.к. `UploadForm` держит свой стейт сам, как сегодня).
- Ошибка генерации (сегодняшний `catch` в `handleSubmit`) возвращает в
  `form` и показывает баннер `msg-err` над кнопкой отправки, как в макете
  (`role="alert"`, с кнопкой закрытия).

### Форма (`UploadForm.tsx`)

- **Файлы**: зона `.drop` с drag&drop (`onDragOver`/`onDragLeave`/`onDrop` +
  клик открывает системный выбор файлов) вместо голого `<input type=file>`.
  Реальный `<input type="file" multiple accept=".pdf,.docx,.txt,.md">`
  остаётся в DOM, скрытый визуально, — так поведение клавиатуры/скринридера
  не теряется. Список выбранных файлов — `.files`/`.file` с иконкой-беджем
  расширения, именем, размером (человекочитаемым, например "2,4 МБ") и
  кнопкой удаления по одному файлу (`.iconbtn`). Зона переходит в компактный
  режим (`.drop.compact`) и текст меняется на "Добавить ещё файлы", когда
  список не пуст — как в макете.
- **Тип документа**: те же три значения (`material`/`specification`/
  `sample`), но как крупные плитки `.tile` в сетке 3 колонки (десктоп) / 1
  колонка (мобильный) вместо капсул — множественный выбор, `aria-pressed`.
- **Количество вопросов**: свитч "определить по образцу" показывается только
  когда выбран `sample` (существующая логика `hasSample`/`useAuto`
  сохраняется как есть), слайдер 1–30 в стиле макета (`.slider`/`.thumb`/
  `.fill`), скрывается, когда включено авто-определение.
- **Типы вопросов**: чипы `.chip`, множественный выбор, как сегодня.
- **Темы для фокуса**: поле `.field`, как сегодня.
- **Готовность к отправке**: кнопка "Создать тест" остаётся `disabled`, пока
  `!canSubmit`; под ней — `.miss-list` с перечислением недостающих условий
  (например "файлы", "тип документа", "типы вопросов" — по тем же
  проверкам, что сегодня определяют `canSubmit`), либо, когда всё готово,
  краткое резюме ("Всё готово: 3 файла, 12 вопросов, один ответ").
- Баннер ошибки конкретного файла показывается через общий `msg-err` (см.
  ниже "Ошибки") — отдельного client-side состояния "файл повреждён" на
  уровне списка файлов не вводим: бэкенд сегодня не возвращает построчный
  статус по файлам, только единая ошибка на весь запрос (`HTTPException` с
  именем файла в тексте, `backend/app/text_extract.py`).

### Ожидание (`GenerationProgress` → полноэкранная панель)

Экран `loading` — панель `.loading.glass1` с кольцевым спиннером и списком
из **двух** реальных этапов (`extract`, `generate`), как уже приходят по SSE
(`ProgressState`, `ExtractDetail`) — без выдуманных промежуточных стадий.
Активный этап получает вращающийся индикатор, пройденный — галочку, деталь
активного этапа (`ExtractDetail.filename` + `processed`/`total`, либо
`detail`-строка для `generate`) показывается под его названием — логика
текста та же, что уже в `GenerationProgress.tsx`
(`extractDetailText`), просто новая вёрстка/классы (`.stages`/`.stage`/
`.st-ic`). Декоративные заготовки карточек (`.skel`) за панелью — по
макету, чисто визуальные, `aria-hidden`.

### Тест (`test`)

- Прогресс сверху, липкий (`.prog.glass1`, `position: sticky`): "Отвечено X
  из N" + полоса заполнения.
- Опциональный баннер `msg-warn` с `result.truncated_files`, если
  `result.truncated` — список файлов с причиной (`partial`/`dropped`,
  переиспользуем существующий текст из `App.tsx`), закрывается кнопкой.
- Карточки вопросов `.card.glass2`, для каждого вопроса:
  - Номер + `qtype`-подпись (человекочитаемое название `q.type`).
  - Текст вопроса через `RichText` (без изменений в парсинге LaTeX).
  - Если в тексте или объяснении вопроса встречается блочная формула
    (`$$...$$` или `\[...\]`), она оборачивается в `.paper .fx` (белая
    непрозрачная подложка, шрифт STIX Two Text) — `RichText` получает новый
    необязательный `display`-режим для блочных формул, не меняя правил
    разбора инлайн-формул (`$...$`/`\(...\)`). Диаграмма (`QuestionDiagram`,
    `diagram.image_base64`) оборачивается в `.paper .fig` с `<figcaption>`
    из `diagram.alt_text`, картинка остаётся тем же `<img>`.
  - `single`/`true_false` — `role="radiogroup"` с кнопками `role="radio"`
    `aria-checked`; `multiple` — `role="group"` с `role="checkbox"`; `short`
    — текстовое поле `.field` в `.field-wrap`. Разметка и роли — по
    `Notes.dc.html` → "Доступность".
  - Варианты true/false выводятся в 2 колонки (`.opts.tf`), остальные — в
    одну (`.opts`).
- Кнопка "Проверить" (`.btn.btn-primary.lg`) + подсказка под ней (как в
  макете: "Неотвеченные вопросы будут засчитаны как неверные").

### Подтверждение при неотвеченных вопросах (новое поведение)

- По клику на "Проверить": если есть вопросы без ответа —
  **не** переводить в `review` сразу. Вместо этого:
  - Подсказка под кнопкой меняется на "Не отвечено вопросов: N. Нажмите
    «Проверить» ещё раз, чтобы завершить — они будут засчитаны как
    неверные" (или похожий текст, финальная формулировка — на усмотрение
    frontend-dev, смысл сохранить).
  - Страница скроллится и переводит фокус на карточку первого неотвеченного
    вопроса (`article.card`, `tabindex="-1"` + `.focus()`, либо focus на
    первый интерактивный элемент внутри — на усмотрение реализации, важно
    чтобы фокус реально сдвинулся, а не просто проскроллилась страница).
  - Это трактуется как один общий "unconfirmed" флаг на весь тест, а не
    per-question: как только пользователь нажимает "Проверить" второй раз
    подряд (не отвечая на вопросы между кликами — но и это не блокируем,
    достаточно, что второй клик всегда подтверждает) — тест переходит в
    `review` как сегодня, пустые ответы засчитываются неверными.
  - Если неотвеченных нет — первый клик сразу переводит в `review` (текущее
    поведение).

### Разбор (`review`)

- Тот же список карточек вопросов, что и в `test`, но:
  - Каждый вариант получает класс `.opt.ok`/`.opt.no`/`.opt.miss` (верный
    невыбранный) + текстовую подпись состояния (`.o-tag`) — не только
    цветом, по правилу макета "не только цвет".
  - Карточка получает `.verdict.ok`/`.verdict.no` в шапке.
  - `short`-поле — `.field.ok`/`.field.no` + иконка в `.fstat`, под полем —
    "Верный ответ: …" (`q.correct_text`), если ответ неверный.
  - Есть `q.explanation` — блок `.expl` с пояснением.
  - Варианты/поля становятся `locked` (клики не обрабатываются).
- После действия "Проверить" фокус переходит на карточку результата
  (`.result.glass1`, `tabindex="-1"` + `.focus()`), как требует
  `Notes.dc.html` → "Доступность".
- Карточка результата: счёт `N из total`, `.dots` — по кружку на вопрос
  (ok/no), кнопки "Пройти заново" (→ `test`, очищенные ответы, тот же
  `quiz`) и "Создать новый тест" (→ `form`).

### Адаптив

- Одна раскладка, без отдельных мобильных компонентов: брейкпоинт
  `720px` (мобильная 360–719px, десктопная от 720px), колонка контента
  `880px` на десктопе, поля страницы `40px`/`16px`, кнопки действий на всю
  ширину на мобильном — точные правила из `Notes.dc.html` → "Адаптивность".
- Плитки типа документа: 3 в ряд на десктопе, 1 колонка на мобильном.
  Верно/неверно остаётся в 2 колонки на обеих раскладках.
- Минимальная область нажатия 44px везде.

### Длинные тесты и производительность

- Карточка вопроса — уровень размытия 2 (`.card.glass2`, blur 14px, одна
  тень); варианты/пояснения внутри карточки не размываются отдельно
  (`.inset`, без backdrop-filter) — так и есть в CSS макета, ничего
  дополнительно настраивать не нужно.
- Карточкам вопросов, если их больше ~30 (можно взять `quiz.questions.length
  > 30` как порог), добавляется `content-visibility: auto` +
  `contain-intrinsic-size` через инлайн-стиль/класс, чтобы браузер не
  рисовал стекло за пределами окна.

### Доступность

По `Notes.dc.html` → "Доступность" и "Состояния элементов":
- `:focus-visible` — контур 2px акцентного цвета, отступ 3px, везде.
- Роли `radiogroup`/`radio`/`group`/`checkbox` на вариантах ответа,
  `aria-pressed` на плитках/чипах, `aria-checked` на свитче
  (`role="switch"`).
- `role="alert"` на ошибке, `role="status"` на предупреждении и на панели
  ожидания.
- Порядок табуляции = визуальному порядку.
- `@media (prefers-reduced-motion: reduce)` отключает все анимации/переходы
  (spin, rise, pulse), вращающийся индикатор ожидания заменяется статичной
  дугой.
- `@media (prefers-reduced-transparency: reduce)` и
  `@supports not (backdrop-filter: blur(1px))` переключают стеклянные слои
  на непрозрачные (`--s1…--s3` вместо `--g1…--g3`, кромка вместо блика,
  `backdrop-filter` выключен, цветные пятна фона скрыты) — те же значения,
  что в `.app[data-flat="1"]` макета, но включаются только этими двумя
  условиями, без ручного UI-переключателя (это не "flat-режим" как
  отдельная фича, а деградация только для пользователей с этой системной
  настройкой/старым браузером).

## User stories / flow

1. Пользователь открывает приложение → видит форму (`form`) с пятью
   секциями, кнопка "Создать тест" неактивна, под ней список недостающего.
2. Перетаскивает/выбирает файлы → секция 1 заполняется списком файлов;
   отмечает тип документа, при необходимости включает авто-количество или
   двигает слайдер, выбирает типы вопросов, опционально вводит темы.
3. Когда форма готова — кнопка активна, под ней резюме. Нажимает "Создать
   тест" → экран `loading` с реальным прогрессом (извлечение текста по
   файлам/страницам → генерация теста).
4. Ошибка на любом из этапов → возврат на `form`, баннер ошибки с текстом
   от бэкенда, форма и её значения сохранены.
5. Успех → экран `test`: прогресс сверху, опциональное предупреждение об
   обрезанных файлах, список вопросов. Отвечает на часть вопросов.
6. Нажимает "Проверить" с неотвеченными вопросами → подсказка с числом,
   фокус переходит к первому неотвеченному. Нажимает "Проверить" ещё раз →
   переход в `review`.
7. Видит вердикты по каждому вопросу, пояснения, итоговую карточку со
   счётом. Жмёт "Пройти заново" → тот же тест с чистыми ответами, либо
   "Создать новый тест" → возврат к форме.

## Out of scope

- Тёмная тема и переключатель тем (иконка в шапке макета).
- Ручной переключатель "без прозрачности" (`data-flat`) как
  пользовательская настройка — только автоматическая деградация по
  `prefers-reduced-transparency`/`@supports`.
- Постепенное раскрытие формы (показ шагов 2–5 только после первого файла).
- Любые изменения бэкенда, схем (`schemas.py`), эндпоинтов или SSE-формата
  прогресса — фича полностью укладывается в существующий API.
- Построчный (per-file) статус ошибки обработки на этапе выбора файлов —
  бэкенд сегодня возвращает одну ошибку на весь запрос.
- Виртуализация/окно рендера для тестов длиннее 30 вопросов сверх
  `content-visibility: auto` (полноценный windowing не нужен).

## Acceptance criteria

- [ ] `frontend/src/index.css` содержит перенесённые токены и классы
      дизайн-системы (светлая тема), Tailwind удалён из зависимостей и
      конфигурации.
- [ ] `App.tsx` управляет явным view-state `form | loading | test | review`;
      тест открывается отдельным экраном, а не под формой.
- [ ] `UploadForm` поддерживает drag&drop, список файлов с индивидуальным
      удалением, плитки типа документа, подсказку "чего не хватает"/резюме
      готовности — без изменения полей `FormValues`/вызовов `api.ts`.
- [ ] Экран ожидания показывает реальные `extract`/`generate` этапы из
      `ProgressState` в новой вёрстке (кольцо, список этапов, деталь
      активного этапа).
- [ ] На экране теста клик "Проверить" при наличии неотвеченных вопросов не
      переводит в `review`, показывает число неотвеченных и переводит фокус
      к первому из них; повторный клик подтверждает переход.
- [ ] Экран разбора показывает вердикт по каждому варианту/полю не только
      цветом (иконка + текстовая подпись), карточку результата со счётом и
