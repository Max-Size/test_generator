# Управление бюджетом контекста при загрузке документов

## Problem

Пайплайн генерации теста (`POST /api/generate`) сейчас не ограничивает размер
загружаемых файлов и грубо обрезает объединённый текст документов перед отправкой
в LLM. Это приводит к трём проблемам:

1. Огромный файл (сотни МБ) проходит через полное извлечение текста и, при наличии
   "тяжёлых" страниц, через платное vision-распознавание — прежде чем что-либо из
   этого может быть отброшено при обрезке контекста. Деньги и время тратятся впустую.
2. Обрезка контекста режет посимвольно, без учёта границ файлов/абзацев — может
   обрубить слово, таблицу или формулу посередине. Если первый файл сам по себе
   длиннее лимита, остальные загруженные файлы целиком выпадают из промпта.
3. Числовой лимит (`max_context_chars = 24_000`) захардкожен и никак не связан с
   реальным контекстным окном используемой модели — при смене модели его никто не
   пересчитывает.
4. Пользователь в UI видит только общую фразу "материал длинный — использована
   первая часть", без информации о том, какие именно файлы обрезаны или не попали
   в тест вообще.

## Current behavior

- `backend/app/main.py`: `total_bytes` каждого файла подсчитывается только для
  логирования (`stage("extract_text", ...)`), нигде не проверяется как лимит.
- `backend/app/text_extract.py::combine()`: склеивает тексты всех файлов в одну
  строку (с заголовками `### <имя файла>`) и обрезает её срезом `full[:limit]` —
  без учёта границ. Возвращает `(text, truncated: bool)`.
- `backend/app/config.py`: `max_context_chars: int = 24_000` — фиксированное
  значение, не связанное с моделью.
- `backend/app/schemas.py::GenerateResponse`: поле `truncated: bool` — единственный
  сигнал об обрезке, без детализации по файлам.
- `frontend/src/App.tsx:49-53`: при `result.truncated` показывает фразу
  "Материал длинный — использована первая часть (N символов)".

## Solution

### 1. Лимит размера файла на загрузке

Новая настройка `max_file_size_mb = 20` (`config.py`). В `main.py`, сразу после
чтения каждого файла (до вызова `extract_text`) — если `len(data)` превышает лимит,
`HTTPException(422, ...)` с именем файла. Дорогая обработка (извлечение, vision) не
запускается для файлов, превышающих лимит.

### 2. `max_context_chars` вычисляется от контекстного окна модели

Новая настройка `polza_model_context_tokens: int` (`config.py`, без дефолта —
обязательна в `.env`, задаётся вместе с `polza_model`; при смене модели значение
обновляется вручную). При старте бэкенда вычисляется:

```
max_context_chars = (polza_model_context_tokens - reserved_tokens) * chars_per_token
```

где:
- `reserved_tokens` — фиксированный запас под системный промпт, врезку анализа
  источника (`_format_analysis`), накладные расходы JSON-схемы и ответ модели
  (пропорционально `max_questions`);
- `chars_per_token` — консервативный коэффициент перевода токенов в символы
  (с учётом того, что кириллица токенизируется плотнее латиницы).

Вычисленное значение логируется при старте (вместо текущего статичного лога
`max_context_chars`). Используется модель из `polza_model` (генерация теста),
а не `vision_model` — контекстный бюджет ограничивает промпт `generate_quiz`/
`analyze_sources`, а не постраничные vision-запросы.

### 3. Обрезка `combine()` по границам файлов и абзацев

Вместо `full[:limit]`:
- файлы укладываются в промпт целиком, по порядку загрузки, пока укладываются
  в оставшийся лимит;
- файл, на котором лимит заканчивается, обрезается по последней границе абзаца
  (`\n\n`), а не посреди слова/таблицы/формулы;
- файлы, идущие после того, на котором лимит закончился, в промпт не попадают —
  осознанно и предсказуемо, а не как побочный эффект среза посередине.

### 4. Детальная обратная связь пользователю

`GenerateResponse` получает новое поле `truncated_files: list[TruncatedFile]`, где
`TruncatedFile` — `{filename: str, reason: "partial" | "dropped"}`. `filename` берётся
из исходного имени загруженного файла. Поле `truncated: bool` сохраняется (истинно,
если `truncated_files` непустой) — фронтенд использует его как раньше для показа
блока предупреждения, но теперь может перечислить конкретные файлы.

## User stories / flow

1. CEO загружает файл размером 35 МБ → бэкенд сразу возвращает 422 с понятным
   сообщением, до какой-либо обработки.
2. CEO загружает 3 файла, первые два укладываются в бюджет контекста целиком,
   третий не помещается вообще → в ответе `truncated_files` содержит третий файл
   с `reason: "dropped"`, UI показывает, что именно он не попал в тест.
3. CEO загружает 1 большой файл, который частично не помещается → `truncated_files`
   содержит этот файл с `reason: "partial"`, обрезка прошла по границе абзаца.
4. Деплоящий меняет `polza_model` на модель с другим контекстным окном → обновляет
   `polza_model_context_tokens` в `.env`, `max_context_chars` пересчитывается
   автоматически при следующем старте бэкенда.

## Out of scope

- Умное/пропорциональное распределение лимита между файлами (например, по размеру
  каждого файла) — не делаем; файлы укладываются строго по порядку загрузки.
- Автоматическое определение контекстного окна модели через API Polza.ai или
  таблицу известных моделей — заменено на явную переменную окружения.
- Изменение лимита числа файлов (`max_files`) — не трогаем.
- Изменение поведения vision-распознавания (`vision_max_pages`, эвристика тяжёлых
  страниц) — не относится к этой задаче.

## Acceptance criteria

- [ ] Файл больше `max_file_size_mb` отклоняется с `422` до вызова `extract_text`
      (нет затрат на извлечение/vision для отклонённых файлов).
- [ ] `max_context_chars` вычисляется при старте из `polza_model_context_tokens`,
      резерва под промпт/ответ и коэффициента символов/токен; логируется.
- [ ] `combine()` не обрезает файлы посреди слова — обрезка только по границе
      абзаца на последнем помещающемся файле.
- [ ] Файлы, не поместившиеся полностью, попадают в промпт целиком по порядку
      загрузки; файлы после точки обрезки не попадают в промпт вовсе.
- [ ] `GenerateResponse.truncated_files` перечисляет обрезанные (`partial`) и
      выпавшие (`dropped`) файлы по имени; `truncated` остаётся согласован с этим
      списком.
- [ ] `frontend/src/App.tsx` показывает конкретные имена файлов из
      `truncated_files` вместо общей фразы.
